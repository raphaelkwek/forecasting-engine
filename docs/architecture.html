01The shape

Everything that computes lives in src/forecasting_engine/, an installable package that never imports Streamlit. The dashboard in app/ is a rendering layer over it — it holds no maths.

This buys three things the proposal explicitly needs. A full backtest can run headlessly from pytest or a CLI, which matters the week runtime becomes a problem. Every stage is unit-testable against known inputs, which is what the functional test matrix deliverable actually requires. And research notebooks import the library rather than reimplementing it, so the join logic that causes look-ahead bias is written exactly once.

One idea borrowed from a heavier architecture: a single frozen RunConfig determines a run end to end, and its content hash is the run id. Reproducibility and caching both fall out of that, without us building an orchestration engine.

03The three contracts

Three types carry the whole system. If these are right, the rest is ordinary code.

FeaturePanel

produced by Raphael consumed by Joash

A dataset that is provably lag-safe. Frozen, and constructible only by align_and_lag().

@dataclass(frozen=True)
class FeaturePanel:
    frame:      pd.DataFrame       # DatetimeIndex; signals + forward targets
    signals:    tuple[str, ...]    # feature columns
    targets:    tuple[str, ...]    # forward-return columns
    lag_days:   int                # observation lag actually applied (>= 1)
    provenance: Provenance         # source files, hashes, build time

No fitting function anywhere in the codebase accepts a bare DataFrame. There is no type-legal way to train on unlagged data.

Forecaster

Joash

Two methods to be a model, plus one to be interpretable.

class Forecaster(Protocol):
    name: str

    def fit(self, panel: FeaturePanel, train: pd.DatetimeIndex) -> None: ...
    def predict(self, panel: FeaturePanel, idx: pd.DatetimeIndex) -> pd.Series: ...
    def describe(self) -> ModelDescription: ...

describe() returns terms and coefficients. That is the sponsor's stated output format, and it is why the polynomial stays the production baseline while tree models are only ever comparators.

RunConfig

shared

Everything needed to reproduce a run. Hashes to the run id stored in DuckDB.

@dataclass(frozen=True)
class RunConfig:
    data:      DataSpec        # csv path + content hash, date range
    features:  FeatureSpec     # screening rule, top-k, horizon
    model:     ModelSpec       # type, hyperparams, or user polynomial
    split:     SplitSpec       # train len, test len, embargo days
    portfolio: PortfolioSpec
    seed:      int

Same config in, same numbers out. Cache keys come free, which is the practical answer to the sponsor's warning that degree-5 searches "might take a lot of time to run".

04Leak-proofing, structurally

The proposal rates look-ahead bias High impact and calls for it to be structurally prevented. Four rules, all enforced in code rather than by convention:

  • Every signal shifts by at least one day inside align_and_lag(). Nothing else may shift anything.
  • Slower series join with merge_asof(direction="backward"). Forward-fill only — bfill and interpolate are banned by a lint rule, not by memory.
  • Revised macro series carry their release date, not their reference date.
  • Walk-forward splits purge overlapping label windows and add an embargo gap.
TRAIN 756d
EMB 5d
TEST 63d
→ window rolls forward, refits, repeats

Overlapping 1–5 day forward returns leak across a naive split. The embargo is the gap that stops it, and PurgedWalkForward is the only splitter in the codebase.

Risk 2's own mitigation — "re-run with one extra day of lag; a feature that loses predictive power signals leakage" — becomes a pytest that runs in CI. The same trick works for Risk 1: a PBO above threshold fails the build rather than being noticed in a review.

07How to do research in this

Notebooks are not banned, they are clients. The dependency runs one way: notebooks import from src/, and nothing ever imports from a notebook. 

%load_ext autoreload
%autoreload 2                # edit src/ in your editor, next cell picks it up

from forecasting_engine.ingest import load, align_and_lag
from forecasting_engine.validation import PurgedWalkForward, rank_ic

panel = align_and_lag(load("data/raw/signals.csv"))   # lag-safe, cached
folds = PurgedWalkForward(train=756, test=63, embargo=5).split(panel)

# everything from here is ordinary ad-hoc pandas. poke at it.
panel.frame[["vix", "spx_fwd_5d"]].rolling(60).corr().plot()

Three lines get you a leak-free, embargoed dataset. Everything after is as exploratory as you like.

The promotion rule

If a cell produced a finding, it stays in the notebook. If it produced a capability — anything you would run a second time — it moves into src/ with a test. That is the whole ceremony.

08Adding a model — the twenty-line version

This is the part that matters most for Joash. A new idea costs one file:

# src/forecasting_engine/models/my_idea.py
class MyIdea:
    name = "ridge-degree3"

    def fit(self, panel, train):
        X, y = panel.matrix(train)
        self._m = Ridge(alpha=1.0).fit(PolynomialFeatures(3).fit_transform(X), y)

    def predict(self, panel, idx):
        X, _ = panel.matrix(idx)
        return pd.Series(self._m.predict(...), index=idx)

    def describe(self):
        return ModelDescription(terms=..., coefficients=self._m.coef_)

Register it, and it is automatically evaluated on the same folds, the same IC and Rank IC, the same PBO and DSR, and appears in the comparison table beside the polynomial baseline, Fama-French and XGBoost. You never write evaluation code. You write models.

This is not hygiene, it is the deliverable. Gap #1 in the proposal is that there is "no structured process to derive, compare and validate alternative specifications against a consistent benchmark." One shared harness behind one protocol is that process. Scoring each model in its own notebook would rebuild the exact gap we were hired to close.

11Still undecided

These block specific pieces of work and are worth resolving with Dr. Burlacu early. Each has a working assumption so Phase 0 is not blocked.

Q1

Which bond index?

The proposal defers this to Sprint 1 with Bloomberg Global Aggregate as the working assumption. It affects the data spec, so it wants answering during Phase 0, not Sprint 1. Assumed: Bloomberg Global Aggregate, column named generically so a swap is a data change.

Q2

What is the forecast horizon?

"Short-horizon" is never pinned down. One day and five days imply different embargo lengths and different target construction. Assumed: 5-day forward return, horizon held as a config field so 1-day is a one-line change. Embargo defaults to horizon + 1.

Q3

How is a crash defined?

Crash recall is a first-class success metric, so the label needs a threshold. Assumed: forward return below the 5th percentile of the training window, with GFC / COVID / 2022 also available as dated windows.

Q4

Is PySR in scope?

It appears in the tools table but nowhere in the sprint plan, and it carries a Julia dependency. Assumed: stretch only, cut early if Sprint 4 is tight.
